# Beginner Manual Testing Interview Questions

1. **What is software testing?** Checking software against requirements and user needs, then reporting differences.
2. **What is a test case?** Preconditions, steps, data, and expected results for a specific check.
3. **What is a test scenario?** A high-level feature or behavior to test.
4. **What is a defect?** Product behavior that differs from expected behavior.
5. **What is severity?** The impact of an issue.
6. **What is priority?** How soon the team should address it.
7. **What is smoke testing?** A quick check that critical build paths work.
8. **What is regression testing?** Checking existing behavior after a change.
9. **What is retesting?** Repeating a failed check after its fix.
10. **What is STLC?** Testing activities from analysis through closure.
11. **What is SDLC?** The full software lifecycle from idea through maintenance.
12. **What is a test plan?** A description of test scope, approach, resources, and schedule.
13. **What is test data?** Input values prepared to exercise test conditions.
14. **What is UAT?** User acceptance testing to see whether a solution meets user needs.
15. **What is boundary testing?** Checking values at and near allowed limits.
16. **What is equivalence partitioning?** Grouping inputs expected to behave similarly.
17. **What is negative testing?** Checking invalid or unexpected inputs.
18. **What is positive testing?** Checking expected behavior with valid inputs.
19. **How do QA and QC differ?** QA improves processes; QC evaluates the product.
20. **What is a test environment?** The configured software and hardware setup where a test runs.
21. **What is a test summary?** Results, coverage, defects, risks, and outstanding work from testing.
22. **What belongs in a defect report?** Summary, environment, reproducible steps, expected/actual results, and useful evidence.
23. **What is a blocked test?** A test that cannot proceed because a dependency or environment prevents a meaningful run.
24. **How would you test a login form?** Check valid/invalid credentials, empty fields, format, masking, keyboard use, and messages.
25. **Why keep execution evidence?** It helps others understand observations and investigate or retest the issue.

Use your own examples and explain your reasoning. These sample answers are practice aids and do not guarantee interview selection.
